# plugin/

## Responsibility

An opencode plugin (Bun + TS, no bundler) that registers the `ollama-cloud` provider with a live model list served from an upstream catalog artifact, wired with official-rate pricing and `reasoning_effort` variants. A second, TUI-side entry adds streaming metrics (TTFT/TPS per LLM step), a live status line, the `/stats` and `/model` commands, and the model card. Server and TUI entries share state only through on-disk files (handoff snapshots, catalog/update caches).

## Design

- `index.ts` — dual V1/V2 server entry (default object): spreads `createV2ServerPlugin()` (`id` + `setup`) and carries the V1 factory under `server` (the ONLY named export is none: opencode's legacy loader calls every exported function as a factory). Owns knob parsing (`pricingKnob`, `stats`, `ensureKnob`) and the V1 hook set: `event` → `capture.handleEvent`, `config` (injects `PROVIDER_CONFIG`, wraps `provider.options.fetch` with `capture.wireFetch` chaining over any user fetch), `provider.models` (`loadCatalog` → `toModelV2`, falling back to `provider.models` with `zeroCost()`). Fire-and-forget `runSelfUpdate` + `ensureTuiPlugin` (V1 only; V2 ignores them).
- `v2-server.ts` — V2 `setup(ctx)`: loads the artifact once, registers the catalog transform (replayed hourly via `ctx.catalog.reload()`), attaches the event-route stats capture unless `stats: "off"`, returns an idempotent cleanup. Options come from `ctx.options` (`catalogUrl`, `timeoutMs`, `pricing`, `stats`, `statsDebug`).
- `v2-catalog.ts` — pure V2 adapter: `modelPatch` (limits, capabilities, cost array, reasoning variants, release epoch) + `applyModelPatch` (in-place upsert; variants merge by id so user `#variant` references survive) + `applyV2Catalog` (provider identity stays ours; artifact models upserted; non-artifact models stay available but rateless — our rate or nothing).
- `v2-capture.ts` — V2 stats capture over the public event stream (`session.step.started` / `session.text|reasoning|tool.input.delta` / `session.step.ended`): TTFT = first delta − step start, decode = last − first, tokens from `step.ended.tokens.output`; per-location filter (the server event stream is global), subagent exclusion via `ctx.session.get`, same collector/handoff persistence as V1. Used because the tested beta (`0.0.0-beta-19425`) does not dispatch the documented session HTTP hooks.
- `v2-types.ts` — structural/local V2 API types (catalog editor, server context, events) in the repo's defensive style; no `@opencode/plugin` runtime or type dependency.
- `catalog.ts` — mirror-race loader: `loadValidated` fetches both `DEFAULT_URLS` (jsDelivr, raw GitHub) in parallel, first response passing the `isCatalog` guard wins, disk cache (`~/.cache/opencode-ollama-cloud/catalog.json`) is the last resort; custom `catalogUrl` is prepended. `isCatalog` is hand-rolled runtime validation (no schema lib) mirroring `catalog.schema.json` only on consumed fields; `toCatalogModel` is the adapter seam projecting `ArtifactModel` (models.dev shape + `x_ollama`) into the internal `CatalogModel` (`familyOf` = id base before `:`, non-string `reasoning_options` dropped).
- `models.ts` — normalizer `toModelV2` to opencode's V1 `ModelV2`: capabilities, `interleaved: { field: "reasoning" }`, `variants` from `reasoningOptions` (`{ reasoningEffort }`), cost mapping (`cachedInput` → `cache.read`, `cache.write` always 0). `zeroCost` is a factory to avoid shared mutable cost objects.
- `stats.ts` — pure measurement core: `summarize` (token-weighted TPS + simple-mean TTFT), `isMainStep` 5-rule gate (subagent header, session `parentID`, compaction exclusion, agent match), `claimPendingWire` (time-based correlation against `message.time.created` + `CLAIM_TOLERANCE_MS` 2 s, pending consumed even when gated), `createStatsCollector` (running totals so trimming `MAX_COLLECTOR_STEPS` 500 can't skew the average; `record` for the V2 direct route), `measurementFromWire` SSE math, `wire-nostream` label only).
- `capture.ts` — `createStatsCapture`: `wireFetch` intercepts only `/chat/completions` (SSE), tees the `ReadableStream` while passing bytes through, records chunk timestamps + final `usage`; `handleEvent` correlates `message.updated` → claim, sweeps on `session.idle`, persists to the handoff; bounded maps (`evictOldest`, 500) and `warnOnce` for seam degradations.
- `handoff.ts` — `createHandoffStore`: per-session `stats-<sessionID>.json` (sanitized id against path traversal), atomic tmp+rename writes, `isHandoffFile` shape guard, `cleanup` (legacy v1 `stats.json` + age/foreign-session eviction).
- `debug-sink.ts` — `appendBoundedLog` (256 KB cap, truncates to 128 KB tail); `statsDebugSinkFor` gates the opt-in claim-instrumentation sink.
- `self-update.ts` — `parseModuleOrigin` (detects npm wrapper under `~/.cache/opencode/packages` via `node_modules` marker), pinned-version guard, `compareSemver`/`decideUpdate`, `fetchLatestVersion` (one registry probe), `runSelfUpdate` (evicts wrapper dir so next `Npm.add` reinstalls, writes `update.json`, optional toast). V1 only: V2 owns its npm cache and ships `opencode2 plugin update`.
- `ensure-tui.ts` — `patchTuiConfigText`: pure text→text jsonc patch (comment-preserving, idempotent, tuple-aware `specEntryMatches`); `ensureTuiPlugin` orchestrates file selection (`OPENCODE_TUI_CONFIG` → `tui.json` → `tui.jsonc` → template), mtime-retry + `.bak` rollback, npm-origin gate. V1 only: V2 auto-loads the package's `./tui` export.
- `tui.tsx` — dual V1/V2 TUI entry (default object): spreads `createV2TuiPlugin()` (`id` + `setup`) and keeps the V1 `{ tui }` object (feature-detection via `pickTuiFeatures`, `session_prompt_right` slot with live line + `↑ version` badge, keymap layer with `/stats` (live re-rendered dialog) and `/model` (snapshot card), `ttlMemo` (60 s) behind `catalogOnce`, throttled fresh handoff reads (~120 ms), event subs + 1 s convergence poll, idempotent `dispose`).
- `tui-v2.tsx` — V2 TUI `setup(ctx)`: `prompt.footer.status` slot (same live line/badge), keymap layer with `/stats` (reactive dialog) and `/model` (dialog alert), `ctx.ui.router` session resolution, `ctx.data.on` + 1 s poll, idempotent cleanup. Same display helpers and silent-degradation contract as V1. Carries `/** @jsxImportSource @opentui/solid */` (V2 loads external packages without rewriting JSX; Bun's default runtime is React) and the commands register from an `app`-slot component because `keymap.layer` needs the Keymap provider.
- `tui-display.ts` — pure string contract: `formatLiveLine`, `pickSessionFile` (cross-session staleness guard), `resolveSessionID` (props → route fallback), `formatStatsDialogBody`/`formatStepRow`/`formatRelativeAge`, `formatModelCard` (quantization as protagonist), plus shared knob scanners `pricingActive` and `configuredCatalogUrl` (reads the other entry's options from opencode config).

## Flow

1. opencode loads `plugin/index.ts` (exports `.` and `./server`). V1 calls `default.server(input, options)`: the factory parses knobs, spawns `runSelfUpdate` and (opt-in `tui: "ensure"`) `ensureTuiPlugin`, then returns hooks. V2 reads `default.id`/`default.setup(ctx)` (`v2-server.ts`): artifact load → catalog transform → event subscription → hourly reload.
2. V1 `provider.models` hook → `loadCatalog(opts)` → URL order (`catalogUrl` first, then jsDelivr, then raw GitHub), all mirrors raced in parallel with `AbortSignal.timeout` (default 5 s); first validated doc wins → cached to disk → `toCatalogModel` per entry → `toModelV2` per model. Unreachable/invalid catalog → `console.warn` → fallback: models.dev's `provider.models` passthrough zeroed with `zeroCost()` (never a wrong price). V2 `catalog.transform` → `applyV2Catalog`: artifact models upserted through `modelPatch`, provider identity enforced, non-artifact models zeroed (same contract).
3. V1 `config` hook wraps `options.fetch` with `capture.wireFetch`; SSE chat responses are tee'd, `measurementFromWire` builds a step (TTFT = first chunk − t0, decode = last − first, tokens from the final usage chunk) and pends it in the session's collector; `message.updated` claims it through `claimPendingWire` + `isMainStep`, then `persist` writes `stats-<sessionID>.json` (monotonic-fingerprint race policy).
4. V2 stats ride the public event stream (`v2-capture.ts`): `session.step.started` opens a step, deltas anchor the stream window, `session.step.ended` records it (same collector/persist). Events are filtered to the plugin instance's location and subagent sessions are excluded by `parentID`.
5. opencode separately loads `plugin/tui.tsx` (export `./tui`). V1 calls `tui(api, options)`: resolves `catalogUrl`/pricing from config or own options, registers the `session_prompt_right` slot and `/stats` + `/model`. V2 reads `id`/`setup(ctx)` (`tui-v2.tsx`): `prompt.footer.status` slot, keymap slash commands, reactive dialogs, `ctx.data.on` + poll. Both render from the same `tui-display.ts` strings and the same per-session handoff file (`pickSessionFile` guard).
6. Boot-time extras (V1 only): `runSelfUpdate` (npm installs only) stages the newer version by evicting the wrapper cache and records `update.json`, which both TUI entries read as a badge; `ensureTuiPlugin` patches `tui.json` so the TUI entry loads on next launch. V2 loads `./tui` automatically and updates via `opencode2 plugin update`.

## Integration

- Consumed by: opencode host — V1 server entry (`main`/exports `.` and `./server` → `plugin/index.ts`, `.server`) and V1 TUI entry (exports `./tui` → `plugin/tui.tsx`, `.tui`); V2 reads the same files' `id`/`setup` (`v2-server.ts`, `tui-v2.tsx`) and auto-loads `./tui`.
- Depends on: upstream artifact `catalog.json` from `srnoob2570/ollama-cloud-catalog` (models.dev shape + `x_ollama`), models.dev provider models as fallback, npm registry for self-update, `~/.cache/opencode-ollama-cloud/` (catalog cache, handoff files, debug logs, `update.json`), `~/.config/opencode/tui.json[.c]`, `jsonc-parser` (only runtime dep; peer `@opencode-ai/plugin >= 1.18`). V2 adds no dependencies: its API types are local/structural (`v2-types.ts`) and `solid-js`/OpenTUI are host-provided.
- Server-side modules: `index.ts`, `v2-server.ts`, `v2-catalog.ts`, `v2-capture.ts`, `v2-types.ts`, `catalog.ts`, `models.ts`, `stats.ts`, `capture.ts`, `handoff.ts`, `self-update.ts`, `ensure-tui.ts`, `debug-sink.ts`. TUI-side: `tui.tsx`, `tui-v2.tsx`, `tui-display.ts` (all also import server modules read-only). Shared cross-process contract: handoff files and `update.json` only.
